# camera-server / camera-client 仕様

対象コミット時点の実装を記述したものであり、計画ではなく**現状**である。挙動を
変えたときは、この文書も一緒に変えること。

- 実装: `rust/camera-server`（配信側）、`rust/camera-client`（視聴側）
- 共有部分: `rust/camera-core`（映像トランスポートと P2P の配線）、
  `rust/camera-ui`（両アプリが出す画面）
- ビルド手順: [`Build.md`](Build.md)。この 2 つだけが OpenCV と libclang を必要とする
- 関連: [`p2p_mode_migration_plan.md`](p2p_mode_migration_plan.md)（直接経路への移行）、
  ISEKAI-link-server の `docs/p2p_connect_spec.md`（プロキシ側の規定。以下 §
  番号はこれを指す）

---

## 1. 全体像

どちらも eframe/egui のデスクトップアプリで、**カメラ映像を MJPEG で 1 対多に
配信する**ことだけを行う。認証・接続の仲介・リレーは ISEKAI link のサービス側が
持ち、アプリはその利用者である。

```
camera-server                                          camera-client / iOS
 ├ カメラ捕捉 (OpenCV)                                   ├ 受信・デコード (OpenCV)
 ├ 映像 QUIC リスナ  ◀────── リレー or 直接経路 ──────▶  ├ 映像 QUIC 接続
 └ Peer Listener ─┐                              ┌─ Peer Connection
                  └──── ISEKAI link Proxy ───────┘
                                │
                         Identity API (Auth0)
```

### 1.1 2 つのモード

両アプリとも起動時に選ぶ。

| | Direct | P2P |
| --- | --- | --- |
| 到達方法 | プロキシが払い出した公開アドレスへ直接 | プロキシ経由（公開アドレス不要） |
| 認可 | JWT を手で渡す | Endpoint 登録 + Grant / Capability |
| 位置づけ | 旧方式。残置 | **現行**。以下は特記なき限り P2P を指す |

Direct は `camera-server` が MASQUE で公開アドレスと証明書を受け取り、
`camera-client` がそこへ直接 QUIC で繋ぐ。P2P はプロキシが接続を仲介し、
リレー経由で始まり、可能なら直接経路へ移る（§1.4）。

### 1.2 映像トランスポート（共通・`camera-core/src/video.rs`）

| | |
| --- | --- |
| プロトコル | QUIC、ALPN `sample` |
| 単位 | **1 フレーム = 1 本の単方向ストリーム**。JPEG をそのまま載せる |
| 順序 | ストリーム ID を連番として扱う。**最新のみ表示**し、遅れたフレームは捨てる |
| MTU | `MaximumMtu` 1248（msquic の下限。CONNECT-UDP 化して外側に収まる大きさ） |
| アイドル | 30 秒。ハンドシェイクのみ 60 秒 |

**最新が勝つ。** 追いつけない視聴者にはキューを積まず、次に受け取れるときの
最新フレームを渡す。ライブ映像では貯めたフレームは遅延でしかなく、遅い視聴者が
他の視聴者や accept ループを止めてはならない。

### 1.3 認証（両アプリ共通）

1. **Auth0 サインイン** — デバイス認可グラント（RFC 8628）。短いコードを画面に
   出し、操作者が任意のブラウザで入力する。得た refresh token で以後は自動更新
2. **Endpoint 登録** — 端末ごとの ECDSA P-256 鍵。公開鍵から Endpoint ID を導出
3. **Endpoint Token** — Identity API が発行。**数分で失効する**ため、セッション中
   自動で再発行する（§5.3 が発行のたびに Auth0 認証状態を要求するので、1 の
   自動更新が前提になる）

手貼りの Auth0 アクセストークン欄も残っているが、期限切れ後は更新できない。

### 1.4 経路（P2P モード）

リレー経由で始まり、双方が相手の観測アドレスを広告して直接経路を試みる。
**multipath を使い、両経路をアクティブに保つ**（`p2p_mode_migration_plan.md`
リスク #24）。

- 直接経路が検証されると `PathAdded` が上がり、**まず backup として保持**される
  （宣言するまで通信は流れない）
- 視聴者が切り替えを要求すると、relay を backup、direct を available と宣言する。
  **リレー経路は破棄されず**、経路ごとの keepalive で温存される
- 直接経路が確立した後の映像はリレーを通らない。確立可否は双方のネットワーク次第
- multipath 非対応の相手には従来の切り替え（`activate_path`）にフォールバックする

## 2. camera-server（配信側）

### 2.1 やること

1. カメラから捕捉し JPEG に符号化する
2. 映像 QUIC リスナを localhost に立てる
3. Peer Listener をプロキシに作り、リレーのバインドレグを張る
4. 接続してきた視聴者へフレームを配る

### 2.2 捕捉

| | |
| --- | --- |
| 取得 | OpenCV `VideoCapture(0)` |
| 解像度 | 640×480 |
| 間隔 | 約 33 ms（≒30 fps）。取得失敗時も同間隔で待って再試行する |
| 符号化 | JPEG、品質 80 |

捕捉は専用スレッドで回り、配信中でなければ送信しない。

### 2.3 視聴者の受け入れ（AcceptPolicy）

| | |
| --- | --- |
| `Auto` | プロキシが Grant を確認済みなので、そのまま束ねる |
| `AutoNotify` | 同上、かつ操作者に見えるよう通知する。**GUI が使う既定** |
| `Manual` | 自動では何も束ねない。操作者が接続 ID を受け取って束ねる |

同時に serve する視聴者数の上限は **8**（`MAX_CONCURRENT_PEERS`）。超えた相手は
待機として報告され、レグが空き次第束ねられる。

### 2.4 Listener のリースを保つ

Peer Listener には期限があり（作成時の `ttl`、既定 3600 秒）、過ぎると制御プレーン
から消える（§8.2.4）。**このアプリは延長を明示的に要求しない。** 延長は owner 自身が
その Listener を読むたびに起きる（§8.2.5）ためで、配信中のカメラは次を叩いている。

| | |
| --- | --- |
| 接続一覧の poll | ストリームが無いとき 3 秒ごと、あるとき 60 秒ごとの控え |
| イベント購読 | 購読時、および保持中もリースの半分ごと |

つまり**配信していれば勝手に延びる**。ここに手当てが要るのは §4 の `Manual` の
場合だけである。

> 以前はこの延長が存在せず、配信中のカメラが 1 時間で Listener を失い、接続と
> リレーエッジを道連れにして映像が止まっていた
> （[ISEKAI-link-server#215](https://github.com/seera-networks/ISEKAI-link-server/issues/215)、
> [#216](https://github.com/seera-networks/ISEKAI-link-server/pull/216) で解決）。

### 2.5 画面

| 区画 | 内容 |
| --- | --- |
| プライバシーポリシー | 初回起動時のみ。同意するまで他は操作できない（§5） |
| 接続設定 | Identity URL / Proxy URL / Auth0 サインイン / 鍵のパス / プロトコル |
| Add a device | ペアリングコードを表示（QR つき）。期限までカウントダウンする |
| Allowed devices | Grant の一覧と失効 |
| Connections | 現在束ねている接続と待機中の相手 |
| Manual exchange | Capability 発行と接続 ID による bind（`Manual` 用、折りたたみ） |
| 映像 | 捕捉中のプレビュー、開始／停止 |

### 2.6 端末に置くもの

| ファイル | 内容 |
| --- | --- |
| `camera-server-endpoint.pem` | Endpoint 秘密鍵。**持ち出してはならない長期の秘密**。0600 |
| `camera-server-auth0.json` | Auth0 のアクセス／リフレッシュトークン。0600 |
| 設定ディレクトリ | プライバシーポリシーの同意記録（利用者ごと） |

前 2 つは作業ディレクトリ相対で、`.gitignore` 済み。

## 3. camera-client（デスクトップ視聴側）

### 3.1 やること

1. 接続できるカメラを一覧する
2. 選んで接続し、映像 QUIC を張る
3. フレームを復号して表示する
4. 経路（リレー／直接）を選ぶ

### 3.2 カメラの一覧

プロキシに問い合わせ、**カメラ 1 台につき 1 行**を出す。Grant は Endpoint に
対するものなので、プロキシは同じ Endpoint の Listener を全部返す。落ちた
camera-server はリースが切れるまで繋がらない Listener を残すため、**同じ owner
では `expires_at` が後のものを採る**（`camera-core/src/cameras.rs`。前提と限界は
そこに書いてある）。この判断は iOS ビューアと共有しており、2 つ書いて食い違うのを
避けるために `camera-core` に置いてある。

一覧に出ないカメラのために、Listener ID と Capability の手入力も残してある。

### 3.3 ペアリング

カメラが表示したコードを入力すると Grant ができ、以後は一覧に出る。
Grant はカメラの Listener ではなく owner に属するので、カメラ側が Listener を
作り直しても有効なままである（§8.8）。

### 3.4 画面

| 区画 | 内容 |
| --- | --- |
| プライバシーポリシー | 初回起動時のみ（§5） |
| 接続設定 | Identity URL / Proxy URL / Auth0 サインイン / 鍵のパス / プロトコル |
| Cameras | 接続できるカメラ、ペアリング、更新 |
| 経路 | リレー／直接それぞれのアドレスと、現在どちらを使っているか、切替 |
| RTT | 1 秒ごとの往復時間を折れ線で表示 |
| 映像 | 受信中のフレーム |

サインイン済み、または Auth0 トークンが入力済みになった時点で、一覧を自動で
取得する。押さないと "none" のままになるのを避けるため。

### 3.5 端末に置くもの

`camera-client-endpoint.pem` と `camera-client-auth0.json`。役割と扱いは §2.6 と
同じ。

## 4. 既知の制約

実装が意図してそうなっている、または直っていない事項。

- **`AcceptPolicy::Manual` の Listener はリースが切れる。** 延長は owner 自身の
  読み取りで起きる（§8.2.5）が、`Manual` では poll もイベント購読も走らないため、
  それを叩くものが無い。既定の `AutoNotify` では起きない。`Manual` を使うのは
  試験用の例だけなので実害は無いが、常駐させるなら手当てが要る
- **映像はリレー運営者に対して秘匿されない。** 映像 QUIC の TLS 証明書と秘密鍵は
  プロキシが発行して配布するため、リレー経由の間は技術的にアクセスし得る。
  プライバシーポリシー §5 に明記してある。直接経路確立後はリレーを通らない
- **Direct モードは旧方式**で、P2P のような自動的な仲介は無い
- **カメラは 1 台目 (`VideoCapture(0)`) 固定**、640×480 で、選択も設定もできない

## 5. プライバシーポリシーの同意

利用にはアカウント登録が必要で個人情報を取得するため、両アプリとも**初回起動時に
全文を表示し、同意するまで他を操作できない**。

- 本文は `docs/privacy-policy.{ja,en}.md` の 1 か所。`camera_core::privacy` に
  コンパイル時に取り込まれ、iOS も FFI 経由で同じものを表示する
- **同意はバージョンに対して**記録する（`VERSION` + 日時 + 表示していた言語）。
  改定して定数を上げると、次回起動時に再度確認する
- 日英を同梱し切り替えられる。egui は CJK フォントを持たないため、システムから
  日本語フォントを借りる。見つからない場合は英語のみを表示し、その旨を出す
- 記録は**利用者ごとの設定ディレクトリ**に置く。起動ディレクトリで同意の有無が
  変わっては記録にならないため
